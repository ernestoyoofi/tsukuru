Pernah nggak, lagi buka website tiba-tiba muncul pesan "DNS_PROBE_FINISHED_NXDOMAIN", "server DNS tidak ditemukan", atau website-nya cuma muter-muter nggak selesai?

Terus ada yang bilang:

"Coba ganti DNS."

Tapi sebenarnya, DNS itu apa? Kenapa DNS bisa bikin website nggak bisa dibuka? Dan kenapa ada banyak jenis DNS record seperti A, AAAA, CNAME, MX, sampai TXT?

Kita bahas dari yang paling dasar dulu.

Apa Itu DNS?

DNS (Domain Name System) adalah sistem yang menerjemahkan nama domain menjadi informasi alamat IP yang dibutuhkan untuk terhubung ke layanan di jaringan.

Simpelnya, DNS itu seperti buku kontaknya internet. Kamu tidak perlu menghafalkan nomor telepon seseorang; cukup cari namanya di kontak. Dengan cara yang mirip, kita cukup mengetik nama domain seperti:

Alamat IP Google bisa berubah dan satu domain juga bisa memiliki beberapa alamat IP. Karena itu, angka di atas hanya gambaran sederhana.

Kenapa tidak langsung pakai IP saja?

Menghafalkan alamat IP untuk setiap website tentu merepotkan. DNS memungkinkan kita menggunakan nama yang mudah diingat, seperti google.com, youtube.com, atau github.com, alih-alih mengingat deretan angka.

Sebenarnya Komputer Mengerti Domain?

Bukan berarti komputer sama sekali tidak bisa membaca domain. Namun, ketika koneksi jaringan dibuat, perangkat perlu mengetahui alamat IP tujuan.

Misalnya, saat kamu mengetik https://example.com, browser perlu mendapatkan alamat IP untuk example.com agar dapat terhubung ke server tujuan. Setelah itu, browser membuat koneksi ke server menggunakan protokol seperti HTTPS.

Jadi, DNS bukan server yang mengirimkan halaman website ke browser. DNS membantu menjawab pertanyaan:

"Informasi alamat untuk domain ini apa?"

Cara Kerja DNS

Saat kamu mengetik nama domain, beberapa pemeriksaan dan permintaan bisa terjadi di belakang layar. Gambaran sederhananya:

1. Browser dan perangkat memeriksa cache

Browser atau sistem operasi mungkin sudah menyimpan hasil pencarian sebelumnya. Jika informasi tersebut masih berlaku, perangkat bisa langsung menggunakannya tanpa mengulang pencarian DNS dari awal.

2. Recursive DNS resolver mencari jawaban

Jika informasi belum tersedia di cache, permintaan diteruskan ke recursive DNS resolver. Resolver bertugas mencari jawaban dan biasanya disediakan oleh ISP, jaringan kantor, router, atau layanan DNS publik.

Jadi, ketika kamu "mengganti DNS", biasanya yang diubah adalah resolver yang digunakan perangkat.

3. Root DNS server menunjukkan arah

Jika resolver belum mengetahui jawabannya, resolver akan bertanya ke root DNS server. Root server tidak langsung memberikan alamat IP example.com; root server menunjukkan server yang mengelola TLD seperti .com.

4. TLD DNS server menunjukkan server domain

Berikutnya, resolver bertanya ke server untuk TLD, misalnya .com, .id, .org, atau .net. Server ini memberi tahu authoritative DNS server yang mengelola domain yang dicari.

5. Authoritative DNS server memberikan jawaban

Resolver kemudian bertanya ke authoritative DNS server, yaitu server yang memiliki informasi DNS untuk domain tersebut. Jawabannya dikirim kembali melalui resolver dan digunakan oleh perangkat.

Kenapa DNS Bisa Bikin Website Tidak Bisa Dibuka?

Jika resolver bermasalah, lambat, memblokir domain tertentu, atau gagal mendapatkan jawaban, domain bisa gagal di-resolve. Browser pun tidak mendapatkan alamat yang dibutuhkan untuk membuat koneksi.

Apa Itu DNS Record?

Jika DNS adalah sistemnya, DNS record adalah data yang memberi tahu informasi apa yang berlaku untuk sebuah domain. Salah satu contohnya adalah pemetaan domain ke alamat IPv4, tetapi DNS record juga digunakan untuk berbagai keperluan lain.

Jenis-Jenis DNS Record

1. A Record

A Record mengarahkan hostname atau domain ke alamat IPv4.

Artinya, namadomainku.id memiliki alamat IPv4 126.121.132.144. Ini bukan redirect; DNS hanya memberikan informasi alamat. Browser kemudian membuat koneksi ke alamat tersebut.

2. AAAA Record

AAAA Record digunakan untuk mengarahkan hostname atau domain ke alamat IPv6.

3. CNAME Record

CNAME (Canonical Name) membuat sebuah hostname menjadi alias dari hostname lain.

Dengan demikian, www.namadomainku.id merujuk ke namadomainku.id. CNAME berguna agar beberapa hostname dapat mengikuti hostname utama tanpa harus menduplikasi informasi alamat IP.

4. MX Record

MX (Mail Exchange) Record menentukan server yang bertanggung jawab menerima email untuk sebuah domain.

MX record memberi tahu server email tujuan ke mana email untuk alamat seperti user@namadomainku.id harus dikirim. Jika ada beberapa MX record, nilai priority yang lebih kecil biasanya memiliki prioritas lebih tinggi.

5. TXT Record

TXT (Text) Record menyimpan informasi teks yang berkaitan dengan domain. TXT record sering digunakan untuk verifikasi domain dan konfigurasi keamanan email seperti SPF, DKIM, dan DMARC.

Contoh SPF:

SPF membantu menentukan server atau layanan mana yang diizinkan mengirim email menggunakan domain tertentu. TXT record juga dapat digunakan untuk verifikasi kepemilikan domain dan konfigurasi layanan pihak ketiga.

6. NS Record

NS (Name Server) Record menentukan server DNS authoritative untuk sebuah domain atau zona.

Sederhananya, NS record menunjukkan server mana yang perlu ditanya untuk mendapatkan informasi DNS domain tersebut.

7. PTR Record

Jika A record memetakan domain ke IP, PTR Record digunakan untuk pencarian arah sebaliknya, yaitu dari IP ke hostname. Proses ini disebut reverse DNS lookup.

PTR record digunakan dalam berbagai kebutuhan jaringan dan penting untuk server email. Server penerima dapat melakukan reverse DNS untuk membantu menilai apakah identitas server pengirim masuk akal.

8. SOA Record

SOA (Start of Authority) Record berisi informasi utama mengenai sebuah DNS zone. Informasinya dapat mencakup authoritative name server utama, email administrator, serial number, refresh, retry, expire, dan nilai yang berkaitan dengan negative caching.

SOA penting dalam struktur dan pengelolaan DNS zone, meskipun biasanya bukan record yang perlu diubah setiap hari.

Apa Itu TTL pada DNS?

TTL (Time To Live) menentukan berapa lama jawaban DNS boleh disimpan di cache sebelum perlu diperbarui.

Nilai tersebut berarti informasi dapat disimpan di cache selama sekitar 3600 detik atau satu jam. Cache membuat pencarian DNS lebih cepat dan mengurangi permintaan berulang.

Kenapa perubahan DNS kadang tidak langsung terlihat?

Jika sebuah record diubah dari IP lama ke IP baru, resolver tertentu mungkin masih menyimpan jawaban lama di cache sampai TTL-nya habis. Karena itu, perubahan DNS tidak selalu langsung terlihat pada semua jaringan di waktu yang sama.

DNS vs. Hosting

DNS bukan hosting. Hosting adalah tempat aplikasi atau website berjalan, sedangkan DNS membantu perangkat menemukan alamat server tersebut.

Gampangnya:

  • Domain = nama tempat
  • DNS = buku petunjuk alamat
  • IP = alamat tempat
  • Hosting/server = bangunannya

Kalau website tidak bisa dibuka, masalahnya belum tentu ada di DNS. DNS mungkin gagal menemukan IP, tetapi bisa juga DNS bekerja normal sementara server mati atau koneksi diblokir firewall.

Kenapa Ada DNS Publik?

Selain DNS dari ISP, kamu juga bisa menggunakan public DNS resolver, misalnya Google Public DNS, Cloudflare DNS, atau Quad9.

Orang biasanya mengganti DNS karena ingin mencoba resolver yang lebih cepat atau stabil di jaringannya, memiliki fitur keamanan tertentu, atau menerapkan kebijakan privasi yang berbeda. Namun, DNS yang lebih cepat tidak otomatis membuat seluruh koneksi internet menjadi lebih cepat. DNS hanya salah satu bagian dari proses koneksi.

Kesimpulan

DNS adalah bagian fundamental dari internet yang membantu menerjemahkan nama domain menjadi informasi yang dibutuhkan perangkat untuk menemukan layanan di jaringan. Tanpa DNS, kita masih bisa mengakses layanan menggunakan alamat IP tertentu, tetapi penggunaannya akan jauh lebih merepotkan.
